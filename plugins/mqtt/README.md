# MQTT 工作台

[English](README.en.md)

在 OxideTerm 中订阅、查看和发布 MQTT 消息，可与串口或 SSH 终端分屏使用。

## 使用

1. 安装对应系统的 ZIP 插件包并启用，确认进程运行与连接密码访问权限。
2. 在连接管理中新建 **MQTT** 连接，填写主机和端口。端口留空时，普通连接使用 1883，TLS 使用 8883。
3. 打开连接，在“订阅”页添加主题过滤器，例如 `devices/+/state`，选择 QoS 后订阅。
4. 切回“消息”页查看实时消息，选择一行查看完整内容。可以把选中消息填入发布区，编辑后发送。
5. 使用宿主现有分屏操作，将工作台与串口终端放在一起。切换页面不停止接收；关闭连接页面会断开连接。

## 功能与边界

- MQTT 3.1.1，TCP、TLS，用户名／密码认证，QoS 0／1／2，保留消息。
- TLS 默认验证系统信任证书与主机名；私有服务器可填写 CA 证书，不能跳过验证。
- 会话与订阅：网络中断后退避重连并恢复当前订阅。认证拒绝或 TLS 错误等待用户重试。
- 客户端 ID 留空时每次打开生成独立 ID；持久会话必须填写固定 ID。同一个 ID 同时连接通常会被服务器互相踢下线。
- 文本、JSON、十六进制内容查看与发布；QoS 0 显示“已发送”，QoS 1／2 等待相应确认。
- 暂停只冻结消息列表，后台仍接收。最多缓存 1,000 条／8 MiB，显示最近 200 条匹配结果；淘汰计数可见。单条内容最多 64 KiB，输入主题和过滤器最多 1,024 字节，最多 32 个订阅过滤器。
- 原始消息只保存在当前连接的内存中，不写入日志或云同步。订阅列表、消息记录、发送草稿不跨关闭恢复。
- 保存的连接配置、凭据安全存储、云同步及 `.oxide` 导入导出由宿主负责；凭据同步遵循宿主开关。
- 首版不提供 MQTT 5、WebSocket、双向 TLS、自动发布或服务器管理接口。

**需要包含插件连接与持续推送能力、版本高于 2.2.4 的 OxideTerm。正式版 2.2.4 不兼容。** 开发中的宿主即使已有代码，版本仍为 2.2.4 时也会被版本门槛阻止；不要降低正式插件的兼容范围。

## 构建与验证

需要 Rust、Node.js 22+。集成测试使用本机 Aedes 消息服务器和 OpenSSL，不连接公共服务器。

```sh
npm ci --ignore-scripts
npm run check
npm test
node scripts/check-host.mjs /path/to/OxideTerm
npm run package
node scripts/verify-package.mjs
```

安装包写入 `dist/`，只包含原生可执行文件、清单、文档与许可证；运行时不需要 Node.js。每个平台应在对应原生环境构建和验收。打包使用插件仓库已有版本准备流程，不创建 Release 或修改市场目录。

发布标签 `mqtt-v<版本号>` 会触发六平台原生构建：macOS、Linux、Windows 的 x64 和 ARM64。每个平台都运行单元测试，并解压安装包执行本机消息服务器与 TLS 集成测试；全部通过后统一发布，由现有市场发布流程收录。

网络协议使用 rumqttc；宿主通信、连接状态和工作台由本插件独立实现。第三方依赖许可随安装包的 `THIRD_PARTY_NOTICES.txt` 提供。
